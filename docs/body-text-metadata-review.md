## 원칙과 실제 범위

- 강의 63개 모두의 기존 overview와 예제 단계 본문을 읽고, 각 강의의 개요 1개와 핵심 단계 1개를 지정했다. 원문 126개에 해당한다.
- 별도 FK 보충 예제 7단계와 INSERT 보충 예제 4단계를 모두 검토했다.
- 대표 학습 노트 16개의 본문 24개를 추가 검토했다.
- 정확한 원문 키 161개. 강조 467구간, 의미 전환 문단 경계 메타데이터 50곳, 인라인 코드 후보 288개. 이는 메타데이터 수이며 실제 렌더링된 스타일 수와 같다고 주장하지 않는다. 동일 단어 반복 강조 여부와 중첩 스타일은 공통 렌더러에서 처리한다.
- 문단 경계 메타데이터 50곳 중 강의 개요·예제 해설의 32곳은 StudyBodyText의 문단 구분 대상이다. 학습 노트의 18곳은 NoteTextProjection이 명시된 경계에만 표시용 개행 두 개를 넣도록 구현했다. SelectableNoteText는 원문 기준 스타일 범위를 표시 위치로 변환하고, 선택 구간은 원문 위치로 되돌려 필기 인용을 저장한다. 이는 적용 경로의 구현 범위이며, 모든 50곳을 실제 화면에서 확인했다는 뜻은 아니다. 실행 테스트와 실기기 검증 결과는 최종 QA에서 별도로 확인한다.
- 원문의 글자·문장 순서·문법·SQL·예제 값·표·문제·정답은 수정하지 않았다. 메타데이터의 키를 원문 전체와 완전 일치시키므로 추후 원문이 바뀌면 이전 표시가 잘못 붙지 않는다.
- 짧고 의미가 이어지는 문장은 그대로 하나의 문단으로 두었다. 별도 예제·개념 비교·주의 또는 결론으로 전환되는 위치만 paragraphStarts로 지정했다.

## 대표 판단 근거

- 모델링 1-1-02: 학생·과목·연결에 붙는 사실을 같은 문단으로 유지하고, 추상화의 결론인 “현실의 모든 정보를 저장하지 않고…” 앞에서만 나누었다.
- INSERT 보충: NAME/양지훈, PHONE/010-****-1003, ID/1003의 각 대응을 굵게 하되 새 카드나 대응별 강제 줄바꿈을 만들지 않는다. 위치 대응 규칙 앞에서만 문단을 나누었다.
- FK 보충: 현재 만드는 EMPLOYEE와 상대 DEPARTMENT의 소속을 굵게 구분하고, 최종 FK 소속 결론 앞에서 문단을 나누었다. 식별자 문자열 자체는 그대로다.
- 긴 노트의 정의→구체 예시, 함수 계열 전환, 비교 규칙→예외에서 문단 경계를 검토·기록했다. 원문 기준 스타일 계산은 preserveSource=true로 유지하고, NoteTextProjection이 18개 명시 경계의 표시 변환을 맡는다. 문장 수나 길이만으로 나누지 않는다.

## 검증 경계

- 이 파일의 정적 substring/중복 경계/전수 63강 검사는 실행했다. 실제 BodyTextRules.firstPhraseIndex의 영문 식별자 경계 조건을 동일하게 대입해도 지정 구간 전부가 검색됨을 확인했다. 인라인 코드 2개(AVG, NULL)는 이미 같은 폰트를 적용하는 긴 코드 구간 내부와 겹쳐 중복 범위가 생략되며 의미나 표시 범위를 잃지 않는다. 렌더러 적용 후 폰·태블릿 캡처, 글자 확대, 기존 저장 기록 동일성 검사는 상위 작업의 최종 QA 기록으로 확인해야 한다.
- 이 메타데이터가 모든 본문에 개별 강조를 작성했다는 뜻은 아니다. 선택하지 않은 기존 본문도 공통 본문 스타일의 대상이며, 특정 문장에 억지 강조를 넣지 않는다.

## 공통 렌더러 추가 읽기 검토

- BodyTextRules는 원문 전체 문자열로 메타데이터를 찾는다. 선택된 161개 본문은 현재 콘텐츠와 완전 일치하고, 원문 수정 시 이전 별도 강조가 적용되지 않는다.
- 강의 개요는 GuideText→StudyBodyText, 예제 단계는 ReadingText→StudyBodyText로 원문을 전달하며 임의 접두 문구를 붙이지 않아 해당 메타데이터 키가 유지된다.
- softBreaks 목록은 없으므로 현재 원문 줄바꿈·공백을 치환하는 경로는 동작하지 않는다. 코드·문자열 공백을 전역 정리하는 동작도 없다.
- SelectableNoteText는 NoteTextProjection의 표시 문자열로 SpannableString을 만든다. 표시된 선택 구간은 sourceQuote로 원문 위치에 다시 대응해 기존 인용 저장 형식을 유지한다. 기존 강조·필기 범위는 displayRange로 표시 위치에 대응한다.
- NoteTextProjection은 지정 경계 앞에 개행 두 개만 추가하며 원문 공백을 삭제하거나 문자열 값을 정규화하지 않는다. 새 개행의 양끝은 동일한 원문 위치로 대응한다. 그 결과 개행만 선택하면 저장할 인용이 없고, 경계를 걸친 선택은 기존 원문의 연속 구간으로 돌아간다.
- displayRange는 시작 경계의 마지막 대응 위치를 사용해 앞의 새 개행을 제외하고, 끝 경계의 첫 대응 위치를 사용해 뒤의 새 개행을 제외한다. 이는 코드 읽기로 확인한 경계 동작이며 Android 실제 선택·저장·복원은 실행 테스트에서 확인해야 한다.
- 본 추가 검토는 코드 읽기와 문자열 범위 검사이다. 과도한 굵기 밀집, 한글 줄바꿈, 큰 글자 실제 화면 품질은 별도의 렌더링 검수가 필요하다.
