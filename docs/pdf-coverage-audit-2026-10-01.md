# 사용자 PDF와 SQL 노트 0.4.1 내용 대조

검토일: 2026-10-01. 대상은 사용자가 제공한 **[꿈꾸는라이언] SQLD 요약노트.pdf** 38쪽과 현재 배포 APK 0.4.1에 실제 들어간 학습 자료다. PDF 1~4쪽의 표지·발행 정보·목차·안내와 학습 본문 5~38쪽을 구분했다.

**앱에 겹치는 학습 내용은 많이 있다. 그러나 PDF의 세부 설명과 문법까지 모두 담았다고 할 수는 없다.** 특히 63강의 개념 목록에 이름만 적힌 항목, 기존 문제 해설에만 등장하는 항목, Oracle 중심 설명 때문에 SQL Server 비교가 빠진 항목이 있다. 반대로 앱이 PDF보다 자세히 설명하거나 PDF의 잘못된 일반화를 피하고 있는 항목도 있다.

이번에는 비교 자료만 작성했다. 앱 코드, 학습 콘텐츠, 문제, 진도·메모·답안, APK는 변경하지 않았다. 추가 여부를 결정할 수 있도록 누락·보강·원문 주의를 나누었다.

## 비교한 실제 자료와 판정 기준

- 앱 로더: `StudyRepository.kt`가 읽는 `content-pack.json`, `course-pack.json`, `course-visuals.json`.
- 기존 개념 노트 41개, 채점 문항 661개와 해설, 강의 63개·예제 95개·자기점검 189개, 그림 27개와 읽기 안내를 함께 검색하고 관련 항목의 실제 내용을 읽었다.
- 현재 APK 내부 세 JSON이 작업 폴더의 앱 자산과 동일함을 확인했다. PDF와 앱 파일 SHA-256은 `evidence/pdf-audit-20261001/inputs.json`에 기록했다.
- PDF는 38쪽을 이미지로 렌더링하고 텍스트와 함께 검토했다. 추출 텍스트에는 그림이나 도형에 가려진 문장이 섞여 있어, 실제 페이지에 보이는 내용을 우선했다. 구매자 워터마크와 PDF 원문 전체는 이 보고서에 옮기지 않았다.
- **충분**: 해당 PDF 소항목의 학습 판단을 앱의 설명·사례로 할 수 있다. 전체 시험 대비가 충분하다는 뜻이 아니다.
- **부분**: 주제나 일부 설명은 있지만, PDF에 있는 구별 기준·문법·조건·예제가 부족하다. 문제나 오답 해설에만 있는 경우도 표시한다.
- **없음**: 관련 학습 내용을 찾지 못했다. 이름이 문항 ID나 무관한 문장의 일부에만 쓰인 경우는 학습 내용으로 세지 않는다.
- **주의**: PDF 자체의 오류·과도한 일반화·DBMS 조건 누락 등으로 그대로 추가하면 안 되는 항목이다. 앱에 없는 항목 수에 합산하지 않는다.

판정은 세부 학습 항목별 AI 비교 검토다. PDF 전체의 모든 SQL을 DBMS에서 실행한 검증이나 사람 전문가 검수는 아니다. 실제 기출 빈도나 현행 공식 출제범위 전체의 포함률을 계산하지 않았다.

## 이미 다루고 있는 내용

엔터티·속성·키·정규화의 기본(`1-1-06`~`1-2-06`, `note-M02`~`note-M06`), NULL·집계(`2-1-15`~`2-1-20`, `note-S06`, `note-S07`), 표준 JOIN·서브쿼리·그룹 함수·윈도우 함수의 중심 원리(`2-1-22`~`2-2-14`), 계층형 질의·PIVOT/UNPIVOT·기본 정규식(`2-2-15`~`2-2-18`), DML·트랜잭션·DCL의 기본은 이미 설명과 예제가 있다. 아래의 '부분'은 이 단원 전체가 없다는 뜻이 아니다.

앱에서 찾는 경로는 **노트 → 강의 순서 → 강의 제목 → 개념/예제**, 또는 **노트 → 개념별 → 해당 노트**다. 문항에만 있는 내용은 일반 본문과 따로 표시했다. PDF와 같은 내용을 설명한다는 사실은 해당 PDF를 직접 인용·수록했다는 출처 증명이 아니다.

학습 본문 **34쪽(5~38쪽)**을 페이지별 세부 항목으로 나눈 결과다. 같은 함수가 여러 쪽에 나오면 별도 행으로 대조했으므로 **'없는 주제 16개'나 '수록률 몇 %'로 읽으면 안 된다.** 일부 '부분'은 핵심 원리를 이미 설명하지만 특정 변형 예제·분류 명칭·암기표가 없는 경우다. 전부 추가해야 한다는 뜻은 아니다. '주의'도 32개의 확정 오류라는 뜻은 아니며, 오류·문맥 누락·추가 검증 필요를 함께 분류했다.

## 그대로 옮기면 안 되는 PDF 설명

다음은 실제 보이는 문구를 공식 DBMS 문서와 대조한 대표 사례다. PDF 전체가 틀렸다는 판정이 아니라, 해당 설명을 앱에 복사하지 말아야 한다는 뜻이다.

| PDF 쪽 | 주의할 설명의 요지 | 확인한 기준과 앱 처리 |
|---|---|---|
| 11 | 모든 열이 NULL인 행을 `COUNT(*)`에서 제외한다는 설명 | `COUNT(*)`는 NULL 여부와 관계없이 모든 입력 행을 센다. 앱 `note-S07`의 기존 설명을 유지해야 한다. [Oracle COUNT](https://docs.oracle.com/en/database/oracle/oracle-database/19/sqlrf/COUNT.html). |
| 16 | 정렬을 지정하지 않은 조회가 입력 순서를 보장한다는 설명 | `ORDER BY`가 없으면 행 순서는 보장되지 않는다. 앱 `note-S09`가 이를 구분한다. [Oracle SELECT의 ORDER BY](https://docs.oracle.com/en/database/oracle/oracle-database/19/sqlrf/SELECT.html). |
| 19 | Oracle에 표준 JOIN 또는 FULL OUTER JOIN이 없다고 읽히는 설명 | Oracle은 해당 구문을 지원한다. NATURAL JOIN의 조인 조건 제한과 일반 WHERE 필터도 구분해야 한다. 앱의 표준 JOIN 설명을 유지한다. [Oracle Joins](https://docs.oracle.com/en/database/oracle/oracle-database/19/sqlrf/Joins.html), [Oracle SELECT](https://docs.oracle.com/en/database/oracle/oracle-database/19/sqlrf/SELECT.html). |
| 29 | OFFSET 유무에 따라 FETCH의 FIRST와 NEXT 사용이 강제된다는 설명 | Oracle에서 FIRST와 NEXT는 서로 바꾸어 쓸 수 있다. [Oracle SELECT의 row limiting](https://docs.oracle.com/en/database/oracle/oracle-database/19/sqlrf/SELECT.html). |
| 36 | 기반 테이블을 삭제하면 참조 뷰도 삭제된다는 설명 | Oracle은 종속 뷰를 무효화하지만 뷰 정의 자체를 함께 DROP하지 않는다. 이 차이를 보강할 수 있다. [Oracle DROP TABLE](https://docs.oracle.com/en/database/oracle/oracle-database/19/sqlrf/DROP-TABLE.html). |

키·정규화·ERD 표기·조인 중복 행·권한 회수 등에 대한 추가 주의 사항은 아래 페이지별 표에 기록한다. PDF 38쪽의 객체 권한 직접 회수와 연쇄 회수는 부여자와 권한 경로 조건에 따라 달라지므로, 단순히 관리자면 언제나 가능/불가능으로 바꾸지 않는다. [Oracle REVOKE](https://docs.oracle.com/en/database/oracle/oracle-database/19/sqlrf/REVOKE.html).
