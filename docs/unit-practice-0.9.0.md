# 0.9.0 단원별 복습·모의고사와 문제 표 표시

사용자가 선택한 결과물은 **현재 앱에 추가**입니다. 새 PDF나 새 앱을 만들지 않습니다. 기존 강의·개념 노트·전체 SQLD 모의 5회는 유지합니다.

## 학습 동선과 수량

노트 → 강의 순서 → **단원별 복습 · 50문항 모의고사**에서 들어갑니다. 개별 강의의 같은 버튼은 해당 강의를 선택한 복습 범위를 엽니다. 기존 모의고사 화면에서도 단원 문제로 이동할 수 있습니다.

|단원|강의 수|추가 복습|추가 단원 모의|
|---|---:|---:|---:|
|1-1 데이터 모델링의 이해|9|27|50문항 × 3회|
|1-2 데이터 모델과 SQL|7|21|50문항 × 3회|
|2-1 SQL 기본|25|75|50문항 × 3회|
|2-2 SQL 활용|18|54|50문항 × 3회|
|2-3 관리구문과 트랜잭션|4|12|50문항 × 3회|
|합계|63|189|750문항 / 15회|

추가 939문항과 기존 661문항을 합쳐 앱의 채점 문제는 **1,600문항**입니다. 기존 강의 자기점검 189개는 별도이며 이 수에 중복 합산하지 않습니다. 강의·유형 필터는 복습 문항에 적용합니다. 각 단원 모의는 해당 단원 모든 강의를 포함하고, 미응시 모의 문항은 평소 연습에서 예약됩니다.

각 단원 모의는 50문항·90분입니다. 실제 과목별 문항 구성과 다른 **단원 집중 연습**이므로 전체 SQLD 합격 판정을 표시하지 않습니다. 기존 전체 시험의 ExamSpec은 변경하지 않습니다. 각 회의 저자 난도 배분은 기초 10·중간 30·심화 10입니다. 이는 저술 목표이며 공식 시험과 난이도가 같다는 실측·전문가 인증은 아닙니다.

63강의 진도 ID와 범위에 연결한 추가 연습이며, 첨부 PDF의 모든 세부 문제 유형이나 현행 공식 출제범위를 빠짐없이 재현했다는 판정은 아닙니다. 개념과 조건이 반복되는 연습도 있으며, 939개가 전부 서로 다른 개념 유형이라는 뜻은 아닙니다.

## 풀이와 답지

- 채점 전의 기존·신규 문제에서 원본 표를 접힌 별도 창 없이 본문에 표시합니다. 태블릿 가로의 넓은 창에서는 문제·SQL·표와 보기를 두 열에 배치합니다. 좁은 창에서는 같은 풀이 화면에서 순서대로 읽으며 스크롤합니다.
- 표의 실제 문자열·NULL·행·열은 보존합니다. 셀 여백을 줄이고 폭을 나눠 쓰며, 여러 작은 표는 공간이 충분할 때 나란히 표시합니다. 읽을 수 없게 글자를 줄이지 않습니다. 물리적으로 넓은 표는 표 내부에서 가로로 이동할 수 있습니다.
- SQL의 공백·들여쓰기는 유지하며 긴 SQL만 내부 가로 스크롤합니다. **코드에 펜으로 필기**를 누르면 기존 문서 좌표 필기·펜 설정을 사용합니다.
- 새 단원 문제의 정답·해설은 **별도 답지·해설**에서 확인합니다. 모의 전체 제출 전에는 답지 경로로 직접 이동해도 정답을 열 수 없습니다. 제출한 보기 순서에 맞춘 빠른 답지와 상세 해설을 전환합니다.
- 이전·다음·확신도·별표·타이머·이어 풀기·단일 문제 채점 시 실전 전환 확인을 유지합니다. 이미 진행 중인 실전이 있으면 그 시험을 이어 풀고 제출 후 새 실전을 시작합니다.

모든 표·긴 지문·200% 글씨를 어떤 휴대폰에서도 스크롤 없이 넣는 것은 불가능합니다. 갤탭의 보통 글씨에서 대표 문제의 동시 표시를 검사하고, 좁은 화면·큰 글씨에서는 가림 없이 읽고 이동하는 것을 검사합니다.

## 콘텐츠와 검토 경계

원본은 `content/part-unit-*.json` 5개이며, `scripts/build_unit_questions.py`가 검토된 원본을 앱의 별도 `unit-question-bank.json`으로 변환합니다. 저자 스테이징은 `qa/workbooks-20261015/`입니다. 기존 content-pack·course-pack을 덮어쓰지 않습니다. SQL·지문을 사용자가 바꾼 것처럼 가장하거나 기존 문제 ID를 재사용하지 않습니다.

검토 증거는 `evidence/unit-practice-20261015/review-*.json`에 각 저술 파일 SHA-256과 전수 검토 ID를 묶습니다. `--check`는 검토 해시·정답 참조·보기·표 열 수·63강 연결·3회×50문항·중복·생성 팩/앱 자산 일치를 확인하며 빌드와 패키징에서 실행합니다. 독립 AI 의미 검토, 제한된 이식 SQL 실행, 구조 검사, 사람 전문가 검수는 구별합니다. 유료 교재 문제나 실제 기출을 복제한 자료가 아닙니다.

신규 자료 전체의 Oracle/SQL Server 엔진 실행·사람 전문가 검수·실제 수험생 난도 보정은 수행하지 않았습니다. 기존 133문항의 검증된 단계별 SQL 해설을 새 939문항 전체에 자동 적용하지 않습니다. 신규 문제는 별도 텍스트 해설과 실제 입력표를 제공하며, 실행 추적으로 가장한 중간표를 생성하지 않습니다.

## 저장 보존과 되돌리기

Room schema 1·백업 schema 3을 유지합니다. 기존 세션은 문제·보기 순서·정답·ExamSpec 스냅샷을 계속 사용하며 제출 기록은 수정하지 않습니다. 단원 세션은 해당 단원의 실제 과목별 문항 수를 ExamSpec에 저장하고 백업 검증에서 별도로 확인합니다. 단원 실전 기록은 전체 SQLD 진단으로 취급하지 않습니다.

변경 전 코드의 복원본은 `backups/unit-practice-20261015/source-before.zip`과 `hashes.json`입니다. 전용 에뮬레이터의 기록 백업은 배포에서 제외한 `private_evidence/unit-practice-20261015/before/`에 보관합니다. 사용자 기기의 전체 기록은 설정에서 직접 내보냅니다. 앱을 제거하거나 데이터 초기화하지 않습니다.

새 단원 세션이 생긴 백업은 구버전 앱이 읽지 못할 수 있습니다. 되돌릴 때는 먼저 0.9.0에서 전체 기록을 내보내 보관하고, 별도 폴더에 코드 복원본을 풉니다. 기기를 초기화하거나 구버전 APK 강제 다운그레이드로 새 기록을 잃지 않도록 합니다. 기존 0.8.1 APK는 `dist/`에 보존합니다.

## 실제 검사

최종 전달 빌드는 `evidence/unit-practice-20261015/build-delivery.log`입니다. Debug/Release APK와 Android 테스트 APK 생성, JVM **108/108**, Debug/Release lint 각각 **오류 0·경고 8**을 확인했습니다. 검사한 경고를 없는 것으로 표현하지 않습니다. `jvm-lint-summary.json`에 실제 XML 결과를 집계했습니다.

최종 앱에서 태블릿 **1280×800dp / 1.0배 전체 101/101**, 휴대폰 **360×800dp / 1.0배 6/6**, 같은 휴대폰 폭 **2.0배 6/6**이 통과했습니다(`instrumentation-summary.json`, 각 프로필 로그). 세 프로필의 반복 검사를 서로 다른 113개 기능으로 합산하지 않습니다. 단원 진입·50문항 예약·정답 사전 차단·보기 순서·제출 보존·답지에서 선택 문제로 반복 복귀·수동 결과 화면의 상태 복원·제외 문항이 있는 기존 시험 재개를 검사했습니다. 신규 모의 1회의 표·SQL 문항과 대표 원본 표의 전체 경계가 지정 태블릿 영역 안에 들어오는지도 확인했습니다.

초기 실행에서 답지 반복 복귀 오류를 재현했습니다(`initial-unit-instrumentation.log`). 해설 정리 후의 전체 검사에서는 정상 본문 문장까지 중복으로 오판한 테스트 선택자 1개가 실패했으며(`duplicate-check-instrumentation.log`), 추가 해설 제목만 검사하도록 보완한 최종 전체 101개가 통과했습니다. 실패 로그를 삭제하거나 성공 수에 합치지 않았습니다. 테스트 APK의 선택자만 변경한 마지막 빌드는 `build-test-selector.log`이며 전달 앱 APK는 `build-delivery.log`와 같습니다.

추가 은행의 939문항은 전부 저자와 다른 담당의 AI 의미 검토를 받았습니다. 정답·해설을 열어 놓고 검토했으며 blind 검수나 사람 전문가 검수는 아닙니다. 앞 문항을 가리키던 조건, 분석 함수의 정렬 기준, 조인 열 변경에 필요한 SELECT 변경, 문제 SQL의 불필요한 정답 노출 조건 등을 수정하고 변경본을 재독했습니다. 초기 저술본의 일부 SQLite 비교는 최종 SQL 변경 전 결과이므로 **최종본 엔진 검증 수치로 인용하지 않습니다**.

보호 대상 원본 콘텐츠·자산 **527파일은 byte 단위 동일**합니다(`content-preservation.json`). 기존 기록을 가진 앱의 MainActivity 실행 후 전체 DB 비교도 동일했습니다(`record-preservation.json`). 세션 5·제출 55·별표 1·텍스트 필기/메모 2·노트 진도 4·강의 진도 5·코드 필기 문서 0이며, 제출 테이블 55행·복구 지점 1행과 모든 상태 필드를 비교했습니다. 새 단원 세션 15회의 정답 채점·백업 검증은 별도 JVM fixture에서 검사했습니다.

이후 기존 개발 서명과 같은 Release 0.9.0/versionCode 17의 `install -r` 성공·콜드 실행·프로세스 동작을 확인했습니다(`release-installed-summary.json`). Release 설치 후 DB를 다시 내보내 비교하지는 않았습니다. 검사 후 원래 화면 크기·밀도·글씨·애니메이션 설정을 복원했습니다. Release의 `TotalTime`은 단일 실행 관찰값이며 성능 보장이나 평균값으로 사용하지 않습니다.

기존 표가 있는 174문항 중 큰 표·복수 표 **11개 대표 사례**를 600/599.5×520dp 컴포넌트에서 렌더링했습니다. 홀수 물리 픽셀 폭에서 짝 표가 아래로 밀리던 반올림 문제를 수정했으며, 스크롤에 잘린 경계가 아닌 **unclipped 경계**로 전체 표 높이와 폭을 검사합니다. 이는 기존 174문항 전체의 질문·보기 동시 화면을 전수 시각 검수했다는 뜻은 아닙니다.

수정한 공통 경로는 `SessionScreens.kt`의 풀이 자료 배치, `UnitPracticeScreens.kt`의 표·SQL·별도 답지, `UnitPractice.kt`의 단원 시험 스냅샷, `StudyRepository.kt`의 별도 은행 로딩·백업 검증입니다. `MainActivity.kt`·`CourseScreens.kt`·`LibraryScreens.kt`에서 기존 동선에 연결합니다. 답지에서 선택 문제로 복귀하는 명시적 요청과 화면 회전의 상태 복원을 구분하며, 제외된 문항이 있어도 이미 생성된 시험 스냅샷을 이어 풀 수 있습니다.

실제 화면은 테스트용 격리 DB를 사용하는 Debug 앱의 API34 에뮬레이터 캡처입니다. 디자인 시안이 아니며 개인 학습 DB의 화면도 아닙니다.
