# 0.11.0 단원 모의고사 동선·실전 버튼

## 실제 변경

모의고사 메뉴에서 단원 5개를 바로 선택하고, 다음 화면에서는 해당 단원의 3개 회차만 선택한다. 회차를 누르면 기존 시간 시작 확인을 거쳐 문제로 이동한다. 타이머가 실수로 시작되지 않도록 시작 확인창은 유지했다. 기존 전체 범위 SQLD 모의고사는 단원 목록 아래 별도 링크로 보존했다.

단원별 복습은 **복습 → 단원별 복습 문제 → 단원 → 강의·유형 선택**으로 분리했다. 홈 보조 도구와 강의의 기존 복습 링크도 같은 복습 경로를 사용한다. 모의고사 선택 화면에 복습 버튼·유형 필터를 섞지 않는다.

미제출 실전(`strict`)에서는 개별 채점과 모르겠어요를 숨기고 이전·다음·전체 제출을 표시한다. 다음은 채운 버튼, 전체 제출은 테두리 버튼이며 마지막 문항에서는 전체 제출을 채운 버튼으로 강조한다. 좁은 화면은 두 행으로 배치하고 터치 높이 48dp를 유지한다. 일반 연습의 채점은 유지한다. 도움 요청의 연습 전환 확인, 전체 제출 확인, 타이머, 답안 저장, 펜·표·해설은 보존했다.

주요 파일: `MainActivity.kt`, `UnitPracticeScreens.kt`, `LearningScreens.kt`, `CourseScreens.kt`, `LibraryScreens.kt`, `SessionScreens.kt`. 버전은 0.11.0/code20이며 같은 개발 서명을 유지한다. 콘텐츠·ID·세션 스냅샷·보기 순서·ExamSpec·채점 엔진·Room 및 백업 형식은 변경하지 않았다.

## 캡처와 한계

모든 학습 화면 캡처는 실제 Compose 앱과 번들 자료를 사용하며, 개인 기록을 노출하지 않도록 독립 인메모리 DB에서 촬영한다. 태블릿 앱 루트는 시스템 표시줄을 제외한 2560×1488px이다. 최종 이미지는 `evidence/mock-navigation-20261018/tablet/mock-flow-*.png`, 휴대폰은 `phone200/`에 둔다.

초기 태블릿 25개 검사는 통과했지만 전환 직후 캡처에 이전 프레임의 보기가 섞인 것을 시각 검수로 발견했다. 원본 문제의 실제 보기는 올바른지 별도 대조했고, 촬영 검사에서 저장소의 변경만 기다리지 않고 현재 화면의 보기 ID·문구·미선택 상태와 이전 복귀의 선택 표시까지 기다린 뒤 native draw 후 촬영하도록 보완했다. 새 문항에서 답을 선택할 때 해당 문항의 답안만 바뀌고 앞 문항 답안은 유지됨도 검사했다. 초기 캡처·로그는 `tablet-initial-pass/`, 중간 검사 동기화 실패는 `tablet-ui-sync-failure/`, `tablet-return-sync-failure/`에 보존하며 최종 PASS 화면과 구분한다. 초기 테스트 빌드의 높이 측정 API 오류도 로그를 보존했다. 제품 코드 오류로 간주하거나 실행하지 않은 검사를 통과로 합산하지 않는다.

## 기록 보호와 되돌리기

변경 전 코드 백업은 `backups/mock-navigation-0.10.1-20261018.zip`(114파일)이다. 실제 QA 앱 DB 원본과 단계별 사본은 배포에 포함하지 않는 `private_evidence/mock-navigation-20261018/`에 보존한다. 초기 AVD 패키지 등록 누락은 직전 검증 원본의 서명을 확인하고 `install -r`로만 복구했으며, 앱 미실행 상태의 기존 DB 전체가 직전 before·after와 동일함을 먼저 확인했다. 초기화·삭제·DB 교체는 하지 않았다.

실제 업데이트 기록 검사는 `after-capture-record-preservation.json`, `after-debug-launch-record-preservation.json`, `after-release-record-preservation.json`과 `finish-summary.json`의 시점·결과를 따른다. Release 실행 후 DB는 같은 버전 Debug를 미실행 접근용으로 설치해 읽었고, 최종적으로 Release20을 다시 설치한다. 원래 표시 설정과 전용 AVD 종료는 별도 결과에 기록한다. 이 검사는 실제 QA DB의 기존 필드 보존 근거이며 물리 기기 설치 또는 SQL 필기문서가 있는 개인 DB 표본을 검사했다는 뜻은 아니다.

코드를 되돌릴 경우 먼저 현재 소스를 백업하고 위 ZIP에서 필요한 화면 소스만 복원한다. 콘텐츠·DB·개인 백업을 덮어쓰지 않는다. 기기에서는 앱을 제거하지 말고 기존 서명과 더 높은 versionCode로 다시 빌드하여 업데이트한다. 개인 기록의 복원이 필요한 경우 앱의 검사·미리보기·복구점 보존을 갖춘 백업 기능을 사용한다.
