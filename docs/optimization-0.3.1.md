# 0.3.1 코드 최적화

범위: 0.3.0의 학습 내용·화면 동선·채점·기록 형식을 유지하면서 반복 계산과 보조 저장을 줄인다. 콘텐츠 팩과 Room 스키마, 백업 v2는 변경하지 않는다.

## 변경한 작업

- 노트별 과거 정답 횟수: 각 행에서 제출 기록과 전체 문제를 중첩 탐색하던 계산을 문제 ID 조회와 학습목표별 1회 집계로 바꾼다. 도움을 본 정답 제외, 반복 풀이 포함, 과거 버전 집계라는 기존 의미를 유지한다. 현재 버전 숙달 지표와 합치지 않는다.
- 검색·연결 연습: 고정된 콘텐츠의 검색 문자열·조회표를 재사용한다. 검색어·필터·문항 제외·모의고사 노출이 바뀌면 필요한 결과를 다시 계산한다. 강의 연결 연습에서는 기존처럼 모든 모의고사 문항을 제외한다.
- 문제 화면: 매초 바뀌는 시간을 초시계 컴포넌트만 구독하도록 분리한다. 문제 본문이 시계 때문에 다시 구성되는 일을 줄인다. 5초 간격 시간 저장, 만료 자동 제출, 시계 이상 판정은 변경하지 않는다.
- 저장: 변경 없는 작업의 Room 상태 조회를 2회에서 1회로 줄인다. Room을 정본으로 매번 읽는 규칙은 유지한다. DataStore 설정 투영은 첫 성공·설정 변경 때 수행하며, 실패하면 다음 저장에서 재시도한다.
- 백업 검사: 제출마다 세션·문항 목록을 처음부터 찾지 않고 세션별 조회표를 사용한다. 중복·정답·보기 순서·문항 버전·역참조 검사를 유지한다.

## 기록 보존

수정 전 소스는 `evidence/optimization-0.3.1-before/source-baseline.zip`, 기존 0.3.0 APK·소스는 `dist`에 유지한다. 개인 DB 및 비교용 원본은 배포 소스에 포함하지 않는다.

0.3.0→0.3.1 제거 없는 업데이트 후 기존 상태의 **모든 필드가 동일**했다. 제출 55개, 세션 4개, 필기 2개, 노트 진도 3개, 강의 진도 1개와 자기점검 답안·위치, revision을 포함한다. 증거: `evidence/optimization-update-preservation.json`. 콘텐츠 두 팩과 채점 엔진·상태 모델도 수정 전 파일과 일치한다.

## 계산량 측정

학습목표 41개·문제 661개·합성 제출 20,000개에 대해 이전 계산식과 새 계산의 전체 결과가 일치했다. 테스트용 목록이 세어 준 접근 횟수는 문제 **356,895,193→661회**, 제출 **820,000→20,000회**다. 워밍업 1회 후 3회 측정 중앙값은 이전 **2,284.146ms**, 이후 **2.967ms**였다. 새 방식에서는 해당 결과를 제출 기록·콘텐츠가 바뀔 때만 다시 계산한다.

이 수치는 PC JDK에서 노트 전체 정답 횟수 집계만 실행한 값이다. 앱 전체 속도 배수로 환산하지 않는다. 증거: `evidence/optimization-note-count-benchmark.json`, `TEST-kr.sqld.study.NoteAnswerCountsTest.xml`.

Room query callback으로 변경 없는 저장 20회의 상태 SELECT가 20회이고 revision이 그대로임을 확인했다. 설정 투영은 초기 동기화 후 진도 저장 20회와 변경 없는 저장 20회 동안 추가 호출 0회였다. 설정 변경·복원 시에는 실행되고, 실패 후 재시도 및 Room 실패 rollback도 통과했다. 이는 불필요한 직렬화·DataStore edit 호출 감소이며 물리적인 디스크 쓰기 횟수 측정은 아니다. 증거: `evidence/optimization-operation-counts.log`.

## 실행 검증

- `scripts/build.ps1`로 JVM 72개 통과, debug/release APK 빌드 성공. release lint 오류 0개·기존 경고 4개. `evidence/optimization-build.log` 및 `evidence/jvm-results/TEST-*.xml`.
- API34 전용 에뮬레이터에서 Android 44개 통과. `evidence/optimization-android-full-final.log`.
- 320×640dp·200% 글씨·다크에서 강의 UI 3개, 초시계 2개, 검색 갱신 1개 재실행 통과. `evidence/optimization-android-font200.log`.
- 새 초시계 테스트는 6회의 시간 갱신 동안 부모 문제 영역의 구성 횟수가 늘지 않고, 표시 시간·0초·역행 경계가 기존과 같음을 확인한다.
- 기존 콘텐츠 및 강의 구조 검증 통과. 콘텐츠 파일은 0.3.0과 해시 동일. Python 회귀 50개와 SQL 엔진 검사는 코드·콘텐츠 변경이 없어 이번에 반복하지 않았다.
- 초기 Android 실행에서는 새 저장 테스트 2개가 Log.i의 Int 반환 때문에 JUnit void 규약에 맞지 않아 테스트 클래스가 시작되지 않았다. 테스트 반환형만 Unit으로 명시한 뒤 test APK를 다시 빌드하고 전체 44개를 재실행해 통과했다. 앱 코드의 추가 수정은 없었다.
- 최종 release APK를 제거 없이 설치하고 홈→노트 검색→강의 자기점검→개념도 열기/닫기→실전 초시계→연습 전환을 직접 조작했다. 저장된 자기점검 답안을 확인했고 초시계가 5,398→5,390초로 감소했다. 마지막에는 QA 시험을 연습으로 전환해 자동 만료 채점이 남지 않게 했다. 캡처: `evidence/optimization-release-{home,search,course,diagram,countdown}.png`.
- 해당 릴리스 프로세스 logcat의 FATAL EXCEPTION/Fatal signal 0건. 인터넷 권한 없음. 에뮬레이터 표시 설정은 이전과 동일하게 복원했다. 실물 Galaxy·TalkBack은 이번에 실행하지 않았다. 최종 결과: `evidence/optimization-qa-summary.json`, 산출물 SHA256: `dist/manifest.json`.

## 성능 해석 범위

반복 계산·조회·설정 투영의 감소를 검증한다. 합성 기록의 집계 시간은 해당 JVM 환경의 참고 측정이며 실제 Galaxy의 실행 속도·배터리 절감률을 뜻하지 않는다. 전체 학습 상태를 JSON으로 저장하는 기존 구조는 유지하므로 장기 기록 증가에 따른 직렬화 비용 자체가 사라진 것은 아니다.
