# SQL 노트 0.2.0 — 강의 주제 보강과 중요도

2026-09-14. 사용자 요청: 흥달쌤 강의 주제의 누락을 보강하고 중요한 내용과 출제 경향을 조사하여 노트·진도에서 강조한다.

## 실제 변경

- 노트 34 → 41개. 신규 7개: 스키마 3단계·데이터 독립성, ERD, 반정규화, 자료형, ALTER/RENAME, VIEW, 관계대수.
- 기존 10개 노트에 DB/DBMS·엔터티 분류·BCNF 보충·문자/숫자 함수·DECODE/NVL2·서브쿼리 분류·분석 함수·계층 경로/순환·정규식 함수 설명을 추가했다. 신규 노트까지 포함하여 설명·예제 등 133개 블록 추가.
- 창작 문항 600 → 661개. 개념 확인 178, 적용 233, 예약 모의고사 5회 250문항. 새 문항 61개의 정답 가림 독립 풀이 및 보기별 이유·해설 검수 기록을 보존했다.
- 학습 핵심 14 / 중요 22 / 기초 보충 5. 목차에 표식·필터·정렬을 제공하고 노트 상단에 집중 포인트와 중요도 선정 이유를 표시한다.
- 공개 교재·강사가 강조한 15개 목표는 별도 표식. 노트에서 출처와 빈도 검증의 한계를 확인할 수 있다. 사용자 즐겨찾기 별과 다른 표시다.
- 홈의 핵심 진도는 현재 내용 읽음, 현재 버전 연습문항의 무도움 개념 정답·적용 정답을 주제 단위로 집계한다. 같은 주제의 반복 정답을 중복 집계하지 않으며 옛 버전 문항·도움 사용·예약 모의고사는 제외한다. 오답 후 다시 풀어 맞힌 현재 연습문항은 포함한다. 한 문제를 맞힌 것이 해당 주제 전체의 숙달이라는 뜻은 아니다.
- 보강 이전 읽음은 보존하면서 현재 내용 읽음과 구분한다. 기존 v2 노트의 읽음도 최초 배포 버전표로 옮긴다. 암기 가리기는 내용이 드러나는 블록 제목과 태블릿 목차도 가린다.

## 출제 경향 조사

[조사 보고서](study-priority-research.md)에 실제 출처를 기록했다. 길벗 2027 SQLD의 공개 저자 분석은 JOIN·함수·서브쿼리·윈도우·GROUP BY/HAVING·WHERE의 비중을 제시한다. 공개면에서 표본·회차·집계 방법은 확인하지 못했으므로 앱에서 공식 확률이나 재현 검증된 빈도로 표시하지 않는다. 강의 시간이나 앱 문항 수를 출제 빈도로 환산하지 않았다.

흥달쌤 공개 강의 목차, 위키북스 목차, 길벗 저자 안내·보충 강좌, Oracle 공식 문서 및 대학 자료를 대조했다. 문항과 예제는 독자 작성이며 유료 강의 본문이나 교재 문제를 복제하지 않았다. DataQ 공식 현행 상세 원문은 여전히 접근 실패다. 기본 시험 설정은 변경하지 않았다.

## 보존과 콘텐츠 검수

`python scripts/verify_priority_update.py`로 기존 600문항 전체 객체와 기존 노트 308개 블록이 이전 해시 그대로임을 확인했다. 기존 5회 모의고사를 연습으로 옮기거나 교체하지 않았다. 0.1.0 APK·소스 ZIP 및 당시 manifest를 dist에 보존한다.

- 새 A 35문항: 부모 AI가 정답·보기 ID를 가린 독립 풀이 후 해설 검수.
- 새 B 26문항: 다른 저술 담당 AI가 정답·보기 ID를 가린 독립 풀이 후 해설 검수.
- 추가 노트/블록 17개 노트 분량을 저술자 외 AI가 읽었다. CUME_DIST의 DESC 조건 설명 1건을 수정 후 재검토했고, BCNF는 보충 설명으로 구분했다.
- A/B 각각 비교·해설 파일은 `qa/priority-*-*.json`, 노트 검수는 `evidence/priority-note-review-*.json`이다. 독립 검수 후 공개 상태만 바뀐 사실을 해시로 확인한다.
- 기존 기록과 합친 661문항의 추적 가능한 AI 답안·해설 검수는 전부 연결된다. 그중 최초 완전 가림 조건이 확인된 문항은 593개다. 나머지의 이전 정답 노출·재검토 한계는 기존 보고서대로 유지한다.

## 실행 검증

- JVM 54개, Python 31개, Android 계측 18개 통과. 큰 글꼴 200%에서 신규 화면 검사 2개도 통과했다. `priority-build-final.log`, `priority-python-tests.log`, `priority-instrumentation-retry.log`, `priority-instrumentation-font200.log`에 결과를 보존했다.
- Android 빌드 성공. lint는 오류 0개·경고 22개다. 경고가 없는 빌드라고 주장하지 않는다.
- Android 14(API 34) 전용 SQLNote_QA 에뮬레이터에서 휴대폰 720×1600/320dpi 및 태블릿 1920×1200/240dpi 화면을 캡처하고 검토했다. 중요도 필터·노트 집중 포인트·출처 대화상자·핵심 진도와 암기 가리기의 태블릿 목차를 확인했다. 캡처는 `evidence/priority-phone-*.png`, `priority-tablet-*.png`에 있다. 변경한 화면 크기·밀도·글꼴은 검사 전 값으로 복구했다.
- 기존 APK와 현재 APK의 서명 인증서가 일치하며, 앱 제거나 데이터 초기화 없이 `install -r`로 설치했다. 초기 빌드의 개발 키 경로 차이를 바로잡아 원래 서명을 사용했다. 개인 키는 작업 폴더나 소스 ZIP으로 복사하지 않았다.
- 화면 검사 전에 설치 전후 DB를 대조했다. 제출 55건·세션 3개(문제·보기 순서·임시 답안 포함)·필기 2개·북마크 1개·노트 기록 2개의 읽음/스크롤/접힘이 그대로였다. 허용된 변화는 콘텐츠 버전·저장 revision·기존 읽음 버전 주석뿐이다. 증거: `evidence/priority-upgrade-preservation.json`, `priority-signature-verification.json`.
- 첫 계측에서 새 화면 선택자 2건과 구형 읽음 버전의 기대값 1건이 실패했다. 실제 UI 구조와 읽음 버전 이관 규칙에 맞춰 테스트를 수정한 후 전체 18개를 재실행해 통과했다. 이전 실패 로그도 삭제하지 않았다.

## 검증 경계

실제 Oracle/SQL Server 엔진 실행, 사람 전문가 검수, Galaxy 실물 기기, TalkBack 음성 및 실제 학습 효과는 검증하지 않았다. 콘텐츠 수량·강의 주제 대응·AI 검수가 시험 합격이나 강의와 같은 깊이를 보장하지 않는다. 개인용 디버그 서명 APK이며 외부 공개 배포는 하지 않는다.
