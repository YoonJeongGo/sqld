# 0.2.1 버그 수정 및 사용성 QA

2026-09-14. 요청: 실제 앱의 버그를 찾고 UI가 직관적인지 확인한 뒤 수정 사항을 보고한다.

## 수정 사항

| 항목 | 기존 동작 | 수정 |
|---|---|---|
| 복습 간격 단축 | 복습 단계가 높은 날 간격 목록을 줄이고 다시 정답을 제출하면 배열 범위 오류 | 현재 간격 수에 맞춰 단계를 보정하고 기존 제출 보존 |
| 이전 문제 세트 재개 | A 다음 B를 만들고 A를 다시 열면 도움 기록과 홈 이어서 공부가 B를 가리킬 수 있음 | 실제로 연 세트를 활성화하고 해당 화면의 문제에 도움 기록 저장 |
| 실전 중 개념 확인 | 전환 저장 전에 이동을 검사해 같은 전환을 두 번 물을 수 있음 | 전환·도움 기록을 저장한 뒤 이동, 저장 실패 시 원래 화면 유지 |
| 목차로 돌아오기 | 검색어·중요도·목록 위치 초기화 | 화면별 상태 보존, 백업 복원 성공 시에만 화면 상태 새로 시작 |
| 일일 복습량 | 홈의 5/20문항 안내와 시작창 기본 10문항 불일치 | 설정한 일일 목표에 맞춰 대상과 시작 수량 일치 |
| 현재 오답 | 도움·헷갈림·찍음 정답까지 오답에 섞임 | 마지막 제출의 오답·미응답만 선택, 과거 이력과 확신도는 보존 |
| 검색 결과 | 표시한 검색 수량과 달리 100개 이후 문항에 접근 불가 | LazyColumn에서 전체 일치 결과 제공 |
| 최근 저장순 | 실제 저장 시각 대신 미래 복습 예정일로 정렬 | 마지막 제출 시각/별표 저장 시각으로 정렬 |
| 설정 버전 | 0.1.0 하드코딩 | 실제 빌드 버전 표시 |
| 형광펜 테마 | 이미 열린 노트의 테마를 바꾸면 이전 배경색이 남음 | 텍스트·필기뿐 아니라 테마 색 변경도 반영 |
| 작은 화면의 오류 표시창 | 200% 글꼴에서 제외 체크박스 설명이 잘림 | 내용 영역을 스크롤 가능하게 변경 |
| 설정 저장 안내 | DB 저장 결과를 기다리지 않고 성공 메시지 표시 | 저장 성공 후에만 성공 안내 |
| 소스 ZIP 포장 | 증거 수집 규칙으로 원본 백업 2개와 상태 JSON 4개까지 포함 | 기록 구조를 검사해 원본 기록 6개·키·DB·원시 logcat 제외, 원본 파일은 보존 |

직관성 개선: 복습 화면의 A~E 대신 실제 단원명을 표시하고, 과목을 바꾸면 그 과목의 단원만 보여 준다. 새 과목에 이전 단원 필터가 남아 빈 목록이 되는 혼동을 줄였다.

## 콘텐츠와 기록 보존

0.2.0의 41노트·661문항·중요도·출처 팩은 그대로다. `evidence/usability-before/source-hashes.json` 및 설치 전 DB 복사본으로 기준을 보존했다. 최초 기준은 제출 55건, 세션 3개, 필기 2개, 북마크 1개, 노트 기록 3개다. 전용 SQLNote_QA 에뮬레이터만 조작하며 다른 에뮬레이터나 사용자 실물 기기는 조작하지 않았다.

화면 QA의 스크롤·노트 열기 같은 의도적인 조작은 별도 기록할 수 있다. 업데이트 보존 검사는 화면 QA 직전의 저장 상태와 비교하고, 테스트는 별도 메모리 DB를 사용한다. 앱 삭제·데이터 초기화는 사용하지 않는다.

## 실행 증거

- 최종 빌드: `testDebugUnitTest assembleDebug assembleDebugAndroidTest assembleRelease lintRelease` 성공. `evidence/usability-fixed-build-verified.log`.
- JVM 55/55, Python 31/31, Android instrumentation 26/26 통과. Android 검사는 기존 18개와 신규 회귀 8개이며 격리 DB를 사용한다. `evidence/usability-instrumentation-final.log`, `usability-python-tests.log`.
- 동일 신규 검사 4개를 이전 0.2.0 APK에서 실행했을 때 4개 모두 실패했다. 이전 세트 재개 시 활성 세트 불일치, 실전에서 연결 노트로 한 번에 이동하지 못함, 기존 형광펜의 테마 색 잔류, 검색 후 복귀 위치 1891→0을 재현했다. 수정판에서는 모두 통과했다. `usability-regressions-before.log`.
- release Lint: 오류 0개, 경고 2개. targetSdk35 안내와 String.toUri 권고로, 이번 수정에서 API 동작이나 의존성을 불필요하게 바꾸지 않았다.
- APK 자체 검사: debug/release 모두 `kr.sqld.study`, `versionCode=3`, `versionName=0.2.1`, 기존 서명 동일, 콘텐츠 팩 바이트 일치. release는 `debuggable=false`. `usability-apk-verification.json`.
- 0.2.0→0.2.1 debug 덮어쓰기 후 저장 상태 전체가 정확히 일치했다. 이어서 release 덮어쓰기 후 설정의 Android 파일 선택창으로 전체 기록을 내보냈으며, 그 payload도 같은 설치 전 상태와 정확히 일치했다. 제출 55건·세션 3개·필기 2개·북마크 1개·노트 기록 3개. `usability-upgrade-preservation.json`, `usability-release-preservation.json`.
- release 실화면: 홈 이어서 공부, 중요도 필터 선택 후 노트 왕복, 과목별 단원, 진행 중 연습, 설정 실제 버전, SAF 백업 저장을 확인했다. 라이트 720×1600/320dpi/100%, 작은 창 720×1200/320dpi/200%, 다크 720×1600/320dpi/200%, 태블릿 1920×1200/240dpi/100%에서 관련 화면을 캡처하고 육안 확인했다. 태블릿 노트는 좌측 목차와 본문을 함께 표시한다.
- 작은 창의 오류 표시창은 하단까지 스크롤하면 제외 체크박스 설명 전체와 취소 버튼을 사용할 수 있다. `usability-release-issue-split-top.png`와 `usability-release-issue-split-bottom.png`. 비클릭 설명을 클릭 대상으로 찾던 자동화 보조 함수는 탐색 시간이 초과됐으나, 실제 스크롤은 완료돼 별도 캡처로 전체 표시를 확인했다. 이를 앱 실패로 세지 않았다.
- release 실행 및 완전 종료 후 재실행에서 해당 앱 PID의 FATAL/ANR 로그를 발견하지 못했다. 재실행 후 이어서 공부와 10문항 목표도 유지됐다. 전용 기기 표시를 시작 기준(720×1600, 320dpi, 글꼴100%, 라이트)으로 복구했다. `usability-release-runtime.json`.
- 본문·문항 등 기존 콘텐츠 9파일의 SHA-256은 시작 전과 모두 동일하다. 화면 QA에서 노트를 열거나 세션을 스크롤한 진도·시간·노트 도움 노출은 정상 조작 기록이며, 새 답안 채점/삭제/초기화는 하지 않았다.

확인한 동선은 개선됐지만 초보자 대상 사용성 조사는 아니다. 복습 필터는 여전히 여러 줄이고 전문 SQL 용어를 사용하므로, 실제 학습자의 첫 사용 이해도까지 검증 완료로 표시하지 않는다.

빌드 과정의 테스트 키보드 API 참조 오류는 수정 후 재빌드했고, JDK 초기화/캐시 잠금 문제는 전용 캐시를 분리해 해결했다. 이전 실패 로그도 보존하며 최종 성공 로그와 구분한다.

수정 전 화면: `usability-before-filter-selected.png`와 `usability-before-filter-back.png`에서 필터·목록 초기화를 재현했고, `usability-before-issue-split.png`에서 체크박스 설명 잘림을 확인했다.

## 배포 및 검증 범위

개인용 release와 debug 빌드를 만들며 기존 개발 서명으로 덮어쓰기 설치한다. release는 디버깅 가능 플래그를 끈 빌드지만 기존 설정처럼 R8 난독화/축소는 활성화하지 않는다. 개발 서명은 스토어 공개용 서명이 아니며 외부 배포·스토어 업로드는 하지 않는다.

코드·에뮬레이터 검증은 실제 수험생의 사용성 조사, Galaxy S24+/Tab 실물, TalkBack 음성, 실제 저용량 장애, 장기 성능 또는 학습 효과 검증을 대신하지 않는다.
