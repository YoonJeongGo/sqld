# 0.3.2 왼쪽 목록 접기

넓은 화면의 상단 `목록 접기 / 목록 펼치기` 버튼으로 왼쪽 주요 메뉴와 개념 노트의 목차를 함께 숨기고 다시 연다. 닫은 뒤에도 버튼은 상단에 남는다. 버튼은 아이콘과 글자를 함께 표시하고 최소 48dp 높이를 유지한다.

- 기본은 펼친 상태이며, 화면 이동과 저장 상태 복원·화면 크기 변경 동안 선택을 유지한다. 새로 시작한 앱의 영구 설정이나 백업 항목으로 추가하지 않는다.
- 좁은 화면에서는 기존 탐색 방식을 유지한다. 문제풀이 화면은 기존처럼 왼쪽 메뉴를 표시하지 않는다.
- 본문 최대 폭 760dp와 읽기·검색·답안 상태를 유지한다. 넓은 태블릿에서는 목록을 숨겨도 본문 글줄이 무한히 길어지지 않는다.
- 콘텐츠, Room 스키마, 백업 형식, 채점 엔진과 저장 코드는 변경하지 않았다. 이전 APK·소스는 보존하고, 업데이트 설치에 `install -r`을 사용했다.

## 실행 검증

- `scripts/build.ps1`로 debug/release 및 Android 테스트 APK 빌드 성공. release lint 오류 0개, 기존 경고 4개. 증거: `evidence/sidebar-build.log`, `sidebar-test-build.log`.
- API34 전용 SQLNote_QA 에뮬레이터, 1280×800dp에서 **Android UI 8개 통과**: 새 목록 테스트 3개, 기존 탐색 2개, 강의 3개. 증거: `evidence/sidebar-android-tablet-final.log`.
- 새 테스트는 두 목록 동시 접기·복원, 실제로 스크롤한 노트의 위치, 확정 제출·미채점 답안·리뷰 보존, 검색어·접힘 상태의 화면 이동과 saved-state 복원, 강의 자기점검 입력·선택 섹션 유지를 검사한다. 테스트마다 독립 메모리 DB를 사용한다.
- 첫 실행은 답안 입력 뒤 목록 버튼의 표시 확인 1개가 실패했다. 키보드를 닫은 직후였으며, Compose idle과 별개인 플랫폼 화면 전환 지연을 고려했다. 테스트가 실제 버튼 표시를 최대 10초 기다리도록 보완한 뒤 같은 8개를 모두 재실행해 통과했다. 실패 시 스크린샷·semantics를 남기며 표시 확인을 생략하지 않는다. 앱 코드 수정은 없었다.
- 새 목록 테스트는 1100dp 이상에서만 실행한다. 휴대폰 전체 테스트에서 건너뛴 결과를 태블릿 통과로 계산하지 않는다.
- 두 콘텐츠 팩과 상태 모델·채점·저장 코드 7개 보호 파일이 수정 전과 동일함을 해시로 확인했다. 증거: `evidence/sidebar-static-checks.json`. 기존 0.3.1 JVM 72개·Android 전체 44개와 Python/SQL 엔진 검사는 이번 UI 변경에서 다시 실행하지 않았다.

최종 release APK에서 노트 목차·메뉴 접기와 복원, 기존 자기점검 답안과 키보드 닫은 뒤 버튼 조작, 태블릿→휴대폰→태블릿 접힘 상태 유지, 200% 글씨 버튼 표시·조작을 확인했다. 해당 릴리스 프로세스의 FATAL EXCEPTION/Fatal signal은 0건이고 인터넷 권한은 없다. 전용 에뮬레이터의 원래 표시 설정을 복원했다. 화면 확인 결과와 캡처는 `evidence/sidebar-qa-summary.json`, `sidebar-release-*.png`에 기록한다. Galaxy 실기기와 TalkBack 검증은 하지 않았다.
