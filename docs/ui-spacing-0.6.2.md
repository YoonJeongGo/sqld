# 0.6.2 — 버튼 간격과 줄바꿈

사용자 요청에 따라 승인된 Canva 색상·카드 디자인을 유지하고 화면 폭이 부족한 조작부를 개선했다. 콘텐츠·채점·메모·진도 저장 방식은 변경하지 않았다. 아래의 실행 결과는 실제 완료된 검사로 마감한다.

## 실제 수정 전 관찰

- 폰320dp, 글씨150%: 전체풀이 모드의 `현재 문제만 채점`이 세 줄로 눌려 둥근 큰 버튼이 됐다. 옆 `모르겠어요`는 한 줄이라 불균형했다. before-phone320-font150-question.png.
- 폰360dp의 홈과320dp/200% 계획 화면: 제목의 두 번째 줄이 `· ERD`로 시작했다.
- 폰320dp/200%: 날짜 버튼의 둘째 줄이 `· 1일차`로 떨어졌다.
- 폰360dp/100%의 예제·자기점검·메모와 태블릿 홈에서 별도의 겹침은 발견하지 못했다. 모든 기기에서 문제가 없다는 뜻은 아니다.

## 바꾼 부분

| 위치 | 변경 | 동작 보존 |
|---|---|---|
| 문제 채점 조작부 | 실제 글자 폭·글자 확대·버튼 안쪽 여백·48dp 이상 터치 영역을 고려해 공간이 부족하면 세로 배치 | 채점/모르겠어요/실전전환 조건과 콜백 동일 |
| 이전·다음·제출, 해설 단계 | 가로와 줄 사이8dp 간격, 남은 공간에 버튼을 억지로 압축하지 않고 다음 줄 배치 | 이동·제출·다시풀기·단계값 유지 |
| 공통 선택 버튼 | 줄 사이 간격4→8dp | 선택/필터 값 유지 |
| 문제 제목 앞 분류·별표 | 분류 텍스트에 남은 폭을 주고 별표 영역을 확보 | 별표 상태/저장 동작 동일 |
| 홈·계획 주제 | 실제 텍스트 폭으로 주제 단위 줄을 구성해 줄머리 구분점 방지 | 표시하는 모든 주제와 원본 plan JSON 동일 |
| 작은 홈 카드 제목 | 기본20sp 대신18sp. 시스템/앱 글자 확대는 그대로 적용 | 본문 글자와 전체 테마는 축소하지 않음 |
| 계획 날짜 | 폭이 부족할 때 날짜와 공부 일차를 의도한 두 줄로 표시 | 날짜 선택·이전/다음·휴식 표시·선택 태그 유지 |
| 좁은 시간표 | 번호·분량은 윗줄, 긴 활동 제목은 아래 전체 폭 사용 | 순번·분량·확장 시간·설명 접기 유지 |

주요 소스: UiComponents.kt, SessionScreens.kt, PlanScreens.kt. 버전0.6.2/code13. 기존 Theme.kt와 저장 엔진은 유지한다.

## 실행 결과

이번 수정의 영향 범위 검사이며 기존0.6.1의 전체64검사와 구분한다.

- Debug·테스트·Release APK 빌드 및 Debug/Release lint: 성공(exit 0, 23분40초). lint는 각각 오류0·기존 경고4개다.
- API34 태블릿1280×800dp/글씨100%: 영향받는19개 검사 모두 통과(실패·건너뜀0, 67.668초).
- API34 폰320×800dp/글씨150%: 위19개 중 계획4개와 채점2개를 다시 실행해6개 모두 통과(실패·건너뜀0, 19.193초). 고유25개 검사로 합산하지 않는다.
- 기존 학습 자료·그림·스키마·저장 엔진 등 보호 대상147파일은 수정 전과 바이트 단위로 동일하다. 앱 코드 변경은 화면3파일뿐이다.
- 수정 후 PNG 직접 확인: 폰320dp/150%의 채점 문구가 한 줄로 표시되고 `모르겠어요`가 별도 행에 배치된다. 폰360dp 홈의 주제가 잘림 없이 한 줄로 표시된다. 폰320dp/200%의 날짜와 일차는 의도한 두 줄로 나뉘고, 주제 둘째 줄은 `ERD`부터 시작한다. 같은200% 문제 화면의 전체 제출은 다음 행에 배치된다.
- 폰320dp/200% 시간표를 직접 확인했다. 번호와 분량이 윗줄, `회상·준비`·`강의`·`PDF 직접 풀이` 등의 활동명이 아래 줄에 표시되며 서로 겹치지 않는다.
- 릴리스 캡처3개의 실제 UIAutomator 좌표에서 채점·이동·제출·날짜·시간 선택14개 조작부를 측정했다. 각 터치 영역이 가로·세로48dp 이상이고, 선택한 버튼 영역끼리 겹치지 않는다. 이 좌표 검사는 실제 클릭 동작 검사와 구분한다. `runtime/geometry-summary.json`에 개별 좌표를 남겼다.
- 최종 릴리스320dp/200%에서 본문 스크롤, 다음 문제(2→3), 이전 문제(3→2), 전체 제출 미리보기, 계속 풀기로 취소를 실제 실행했다. 모두 정상이며 이 수동 조작으로 답안을 제출하지 않았다. 채점·모르겠어요 동작은 별도 임시 DB를 쓰는 자동 검사에서 확인했다.
- 최종 릴리스 태블릿1280×800dp 홈을 직접 확인했다. 두 열 배치와 학습 계획·이어서 공부 버튼에 겹침이나 문구 잘림은 없었다.

- 기존 학습자(user0)의 갱신 전후 전체 백업 payload SHA-256이 동일하다. 제출55개·세션5개·메모2개·강의 진도5개를 포함한 전체 기록을 보존했다. 원시 백업은 개인 복구용으로만 남기며 배포 ZIP에 포함하지 않는다.
- 별도 QA 사용자(user10)의 업데이트 직후 백업도 전체 payload가 동일했다. 이후 강의 화면을 방문하면서 기존 동작에 따라 도움 노출1건이 추가되고 진도 위치·세션·revision 필드가 변했으므로 최종 QA 백업까지 전체 동일하다고 표현하지 않는다. 기존 노출41건과 제출11개·메모1개·선택 답안·보기 순서·세션 스냅샷은 동일하다. 세션4개·강의 진도2개라는 수량도 유지됐다. 세부 비교는 `runtime/record-preservation.json`에 있다.

이번 변경에서 JVM·Python 전체 검사나 기존64개 전체 UI 검사를 다시 실행했다고 주장하지 않는다.

## 근거와 실행

- 증거: `evidence/ui-spacing-20261006/` 및 `runtime/`. before/after 화면은 전용 API34 에뮬레이터 캡처이며 실제 Galaxy 화면은 아니다.
- 빌드: `scripts/build.ps1 -Tasks assembleDebug,assembleDebugAndroidTest,assembleRelease,lintDebug,lintRelease -Offline`.
- 설치: `dist/SQL-note-0.6.2-release.apk`를 같은 서명으로 덮어 설치. 기존 앱을 제거하거나 기록을 초기화하지 않는다.
- 소스: `dist/SQL-note-0.6.2-source.zip`. 원시 개인 백업·user0 화면·DB·서명 키는 제외한다.
- 되돌리기: `backups/ui-spacing-before-0.6.1-20261006.zip`과 `source-before.json`으로 변경 파일을 선택적으로 복구한다. 앱 버전 다운그레이드 대신 이전 소스를 더 높은 versionCode로 빌드해 기록을 유지하는 업데이트를 사용한다. 자동 다운그레이드나 전체 덮어쓰기 복구는 실행하지 않았다.

실물 Galaxy/S Pen/TalkBack/외부 키보드, 가능한 모든 화면 폭과 글자 설정 조합은 이번 표본 검사로 검증 완료라고 하지 않는다.
