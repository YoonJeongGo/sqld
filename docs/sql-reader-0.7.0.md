# 0.7.0 — SQL을 직접 따라 읽는 해설과 코드 위 필기

작성일: 2026-10-07. 앱 버전 0.7.0 / versionCode 14. **작은 화면의 SQL 첫 줄 잘림을 수정한 최종 빌드에서 자동 검사를 다시 통과했고, 실제 Release 화면과 업데이트 기록 보존을 확인했다.** 아래 결과는 전용 에뮬레이터와 명시한 콘텐츠 검사 범위이며, 실물 Galaxy Tab/S Pen·Oracle 실행·사람 전문가 검토·학습 효과 검증은 포함하지 않는다.

기존 Kotlin/Compose 학습 앱에 별도 해설 자료와 SQL 필기를 연결했다. 원래 문제의 원문·문제/보기 ID·정답·난이도·세션 snapshot을 새 해설로 교체하지 않는다. 기존 63강·95예제·189확인문제와 기존 풀이 해설은 유지하는 구조다. 원본 동일성의 실제 검사 결과는 아래 실행 결과에서 별도로 확인한다.

## 화면과 학습 흐름

- SQL을 읽는 문제는 넓은 화면에서 **왼쪽 문제 또는 해설 / 오른쪽 SQL·원본 테이블**로 배치한다. 사용자가 마지막에 지정한 방향을 따른다. 좁은 화면은 위쪽 SQL / 아래쪽 문제 또는 해설로 배치한다.
- 아직 채점하지 않은 문제에는 답안 선택만 표시한다. 새 단계 해설·현재 구문 강조·중간 결과표는 기존 정답 공개 시점 이후에만 열린다. 선택만으로 채점하거나 다음 문제로 넘기지 않는다. 실전 모의고사의 개별 채점과 다른 학습 자료 이동은 기존 연습 전환 확인을 유지한다.
- 채점 후 `따라 읽기 / 기존 해설 / 문제·답안`으로 전환한다. 이전·다음은 사용자가 직접 누르고, 단계와 `이 구문의 기초` 펼침 상태는 모드 전환·화면 재생성 때 보존한다. 자동 재생은 없다.
- SQL은 흰 바탕과 검정 글씨, 현재 구문은 같은 파란 사각 배경(`#D9E9FF`)과 굵은 글씨로 표시한다. 관련 해설 표현과 표의 행/셀도 같은 색을 쓰되 `현재` 등 글자로 함께 구별한다. 글자를 가리는 연결선은 추가하지 않는다.
- SQL은 줄바꿈 없이 양방향 이동·확대할 수 있다. 현재 단계의 첫 강조 부분이 화면 밖에 있으면 그 부분을 보이는 위치로 옮긴다. 원본 테이블과 학습용 중간·결과표는 제목으로 구분하며 각각 필요한 방향으로 스크롤한다.
- 코드 없는 객관식은 문제와 보기 중심으로 간격을 줄이고 부가 조작은 접을 수 있게 한다. 긴 문제·200% 글씨·작은 분할 화면까지 항상 한 화면에 담는다고 보장하지 않고 필요한 스크롤은 남긴다. 코드가 없는 문제에 SQL 실행 단계를 만들지 않는다.
- 개념 노트와 63강의 관련 노트 연결부에서 작은 표로 시작하는 별도 예시를 연다. 암기 가리기 상태에서는 새 학습 링크를 숨기며, 설명 공개 후 표시한다. 같은 예시가 여러 관련 노트에 연결돼도 강의 안에서는 중복 표시하지 않는다.

## 적용 범위와 정확성

현재 정본의 적용 목록은 [문항별 적용·미적용표](sql-walkthrough-coverage.md)와 `content/sql-walkthroughs/coverage.json`이다. 기존 문항 661개 중 별도 SQL 필드가 있는 217개를 분류했고, 새 단계 해설은 133개, 기존 해설을 유지하는 SQL 문항은 84개다. 별도 SQL 필드가 없는 444개는 본문이나 보기에 SQL이 있을 수 있으므로 전부 순수 개념 문제라는 뜻은 아니다. 작은 학습 예시 1개를 더해 134개 자료, 875단계, 중간·결과표 873개를 제공한다. 모든 SQL 문항에 새 해설을 구현했다고 보고하지 않는다.

적용 유형은 WHERE/NULL 조건, JOIN·외부 조인·중복, 집계·GROUP BY·HAVING, SELECT 계산·DISTINCT·정렬, 서브쿼리·상관 서브쿼리, 집합 연산, 일부 윈도 함수다. 원본 값의 대입, 남거나 제외되는 행, NULL 확장, 그룹의 집계 대상, 현재 파티션과 프레임을 실제 값으로 설명한다. ORDER BY 없는 결과는 행 순서를 보장하지 않는다.

검증 범위가 부족한 Oracle 전용 함수·계층형 질의·PIVOT·그룹 확장·상태 변경 등은 기존 해설로 남기고 문항별 이유를 기록한다. 사용자 SQL·입력표·보기·정답·DBMS 조건이 바뀌어 원문 snapshot과 맞지 않으면 이전 새 해설을 붙이지 않는다.

자료의 SQLite 비교 검산은 Oracle 실행 결과가 아니다. 실제 비교 엔진·버전·변환한 SQL은 `evidence/sql-walkthroughs-20261006/engine-checks.json` 및 각 해설의 verification에 있다. 최종 앱 검사, Python 값 계산/SQLite 검산, 독립 AI 읽기 검토, 사람 검토·물리 DB 실행은 별개다. 물리 실행 순서·실제 임시표·실행계획 실측으로 설명하지 않는다.

## 펜 필기와 보존

- SQL 옆 작은 원형 펜 버튼을 누르면 펜/형광펜/획 지우개, 기본 색상과 HEX, 굵기·불투명도, 되돌리기/다시 하기를 설정한다. 실제 터치 영역은 48dp다. 지우개는 닿은 획 전체를 지운다.
- 기본 손가락은 SQL 문서 이동, stylus는 필기다. `손가락으로도 필기`를 켜면 한 손가락은 필기, 두 손가락은 이동이다. 필압은 0..1로 제한해 펜 굵기에 반영한다. 펜 도구/지우개 도구 구분과 취소 이벤트를 처리한다.
- SQL 텍스트와 획은 같은 고정 문서 좌표를 사용한다. 화면 너비 때문에 SQL을 다시 줄바꿈하지 않고, zoom/density 변환을 둘에 함께 적용한다. 화면 회전이나 해설 단계 변경으로 이미 완료한 획의 문서 좌표를 다시 계산하지 않는다.
- 펜을 떼면 로컬 초안을 즉시 반영하고 Room에 저장한다. 저장 실패 시 ViewModel 초안을 유지하며 상태 줄과 펜 설정의 `필기 저장 다시 시도`로 재시도한다. 저장에 성공하지 않은 초안은 앱 프로세스 종료까지 영속 보존됐다고 주장하지 않는다. 펜다운 상태에서 취소·회전된 미완료 획은 저장하지 않는다.
- 원문 fingerprint와 SQL SHA-256을 문서 ID에 결합한다. 같은 문제 ID라도 원문·표가 바뀌면 이전 필기를 새 코드에 붙이지 않고 이전 문서를 보존한다. 실제 데이터 연결은 문서 ID로 하며 이름 표시값을 키로 사용하지 않는다.
- 입력/저장 상태 줄은 고정 32dp, 넘치는 문구는 한 줄 생략 후 설정 창에서 전체 문구를 제공한다. 저장 상태에 따라 코드 화면을 밀지 않는다.
- 문서·이력·획 ID, 좌표의 유한성/범위, 지운 획 참조, cursor, 펜 속성과 용량 한도를 검사한다. 문서 2,000개, 문서당 이력 2,000개, 총 이력 20,000개, 총 좌표 200,000개, 한 획 좌표 4,000개가 안전 한도다. 긴 획이 한도를 넘으면 그 미완료 획을 저장하지 않고 나눠 쓰도록 알린다.
- 실물 Galaxy Tab/S Pen의 지연, 틸트, 팜리젝션, 하드웨어 지우개 버튼을 검증 완료라고 주장하지 않는다. 합성 MotionEvent 검사는 기기 센서 검사와 다르다. OS 저지연 잉크/예측 입력과 필기 문자 인식은 이번 구현에 없다.

## 저장 형식과 업데이트

`StudyState.inkDocuments`를 기본값 빈 목록으로 추가했다. Room 테이블 schema 1을 유지하고 destructive migration을 추가하지 않았다. 기존 제출·보기 순서·답안·타이머·메모·진도·복습·별표의 저장 필드는 삭제하지 않는다. 복원 성공 시 오래된 잉크 초안을 비우고, 복원 epoch가 다른 이전 저장 콜백은 복원한 기록을 덮지 못하게 한다.

**JSON 학습 상태와 백업 envelope는 schema 3이다.** 기존 schema 1/2 백업은 가져올 수 있다. 새 필기가 없는 경우도 새 백업은 schema 3으로 내보낸다. 0.6.2 이하 구버전은 schema 3 백업을 거부한다. 새 잉크가 있는 백업을 구버전에서 읽으면서 필기를 조용히 버리지 않도록 한 경계다. 백업 버전 숫자만 2로 바꾸어 가져오지 않는다.

설치 전 앱의 `설정 → 전체 기록 내보내기`로 기존 백업을 유지하고, 같은 서명의 0.7.0 APK를 기존 앱 위에 설치한다. 앱 제거·데이터 삭제가 필요하지 않다. 전체 복원은 기존 검사·전후 수량 미리보기·직전 복구 지점 보관·원자적 교체 흐름을 따른다. 새 복원 미리보기에는 SQL 필기 문서 수도 있다.

## 실행법

```powershell
Set-Location D:\SQLD
python scripts/validate_content.py --strict
python scripts/validate_walkthroughs.py
.\scripts\build.ps1 -Tasks assembleDebug,assembleRelease,testDebugUnitTest,assembleDebugAndroidTest,lintDebug,lintRelease -Offline
```

새 해설의 정본은 `content/sql-walkthroughs/`이다. `scripts/build_walkthroughs.py`는 이 별도 자료와 앱 미러를 생성하며 기존 `part-*.json`이나 63강 정본을 덮어쓰는 작업이 아니다. 원문 변경 후에는 해설의 값·정답·DBMS 조건·강조 위치를 다시 검토해야 한다. 예전 63강 원본 ZIP의 생성기로 현재 자료를 무작정 다시 만들지 않는다.

기기 검사 대상은 root가 확인한 전용 SQLNote_QA 에뮬레이터나 사용자가 지정한 기기다. 테스트는 별도 DB를 사용하며 배포 앱의 기본 DB에 테스트 답안을 넣지 않는다.

```powershell
# 설치 대상 기기 ID와 APK 서명을 확인한 뒤 실행
adb -s <기기ID> install -r dist/SQL-note-0.7.0-release.apk
# 빌드·검사 마감 후 패키징
python scripts/package_artifacts.py --build-type release
```

패키징 산출물 경로는 `dist/SQL-note-0.7.0-release.apk`, `dist/SQL-note-0.7.0-debug.apk`, `dist/SQL-note-0.7.0-source.zip`, `dist/manifest.json`이다. 실제 전달 파일의 목록·크기·SHA-256은 패키징 후 생성한 `dist/manifest.json`으로 확인한다. 아래 빌드 APK 검증과 ZIP 생성·전달 여부는 구분한다.

패키징은 원본 해설→앱 assets→APK의 파일 목록과 바이트를 대조한다. 코드·콘텐츠·QA 검토 스크립트는 포함하고 개인/QA 사용자의 원시 백업·DB·필기/답안 payload·서명 키는 제외한다. 변경 전 백업 ZIP과 내부 경로 메타데이터가 있는 `source-before.json`은 로컬에만 보관하고 공유 ZIP에 넣지 않는다. APK assets도 같은 학습자 기록 구조 검사를 통과해야 한다. 시험용 코드 fixture와 독립 콘텐츠 정답 대조 자료는 설치된 학습자의 저장 기록과 구분한다.

## 실제 실행 결과

Release 폰 화면에서 SQL 표시 영역이 작아 첫 줄이 잘리는 결함을 발견했다. 글자 배율을 반영한 SQL 최소 높이를 확보하고, 채점 후 중복 상태를 헤더로 옮기고, 하단 조작부를 정리했다. **이 수정이 들어간 최종 앱으로 태블릿 전체 78개, 320dp/150% 글씨 10개, 320dp/200% 글씨의 선택 범위 4개를 다시 실행해 모두 통과했다.** 최종 Release APK도 따로 설치해 실제 화면과 클릭을 확인했다. 서로 겹치는 검사 수나 이전 버전의 검사 수를 합산하지 않는다.

### 성능과 파일 크기

작은 인덱스를 먼저 읽고 개별 해설은 필요할 때 읽으며 최대 6개를 캐시한다. 지연 읽기·캐시 제한은 동작 검사로 확인했다. SQL 줄 위치는 원문이 바뀔 때만 계산하고 보이는 줄을 그린다. 긴 중간 표는 제한된 뷰포트의 LazyColumn으로 행을 표시한다. 134개 자료와 런타임 인덱스 JSON 합계는 1,448,306바이트다.

최종 Release APK는 이전 0.6.2의 17,728,145바이트에서 18,176,370바이트로 **448,225바이트(+2.53%) 증가**했다. 이는 실제 파일 크기 비교다. 로딩시간·메모리 사용량·필기 지연·프레임 시간의 전후 벤치마크는 하지 않았으므로 속도나 메모리 개선율을 보고하지 않는다.

## 되돌리는 방법

1. 현재 버전에서 schema 3 전체 기록을 내보내고, 업데이트 전 schema 2 백업도 별도로 보관한다.
2. 화면 변경만 되돌릴 경우 로컬에 보관한 `backups/sql-reader-before-0.6.2-20261006.zip`과 `evidence/sql-reader-20261006/source-before.json`을 참고하여 해당 UI 파일을 선택적으로 복구한다. 두 자료는 공유 ZIP에 포함되지 않는다. 새 필기를 이미 저장했다면 schema 3 읽기·잉크 보존 코드까지 구버전으로 되돌리지 않는다.
3. 기존 앱을 제거하거나 APK 강제 다운그레이드를 하지 않는다. 필요한 경우 schema 3 보존을 유지한 수정 소스를 더 높은 versionCode로 빌드하여 같은 서명의 업데이트로 설치한다.
4. 업데이트 전 백업으로 전체 기록을 교체하면 그 백업 이후의 새 답안·진도·필기는 반영되지 않는다. 이는 자동 병합이 아니므로 현재 기록을 먼저 백업하고 복원 미리보기를 확인한 뒤 선택해야 한다. 이번 작업에서 강제 다운그레이드나 기록 초기화를 실행하지 않는다.

실물 기기·사람 전문가 검토·전체 Oracle/SQL Server 엔진·학습 효과/합격 보장 범위는 별도의 증거가 없는 한 미검증이다.
