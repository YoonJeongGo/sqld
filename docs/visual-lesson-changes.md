# 63강 통합 변경 목록

작성일: 2026-09-29. 상태: **정본 콘텐츠와 표시 코드에 적용 완료**. 기준은 `content/course-pack.json` 및 `content/course-visuals.json`의 `2026.09.29.1`이다. 이 상태는 콘텐츠 반영을 뜻하며 실기기 QA, 사람 전문가 검수 또는 학습효과 검증 완료라는 뜻이 아니다.

기존 앱과 63강을 유지하면서 27장의 독립된 그림 예제를 연결했다. 원래 설명이 정확하고 구체적인 경우 재작성하지 않았다. 분류는 유지18강, 설명 보완5강, 오류 수정3강, 그림 안내 추가37강이다. 오류 수정3강에도 그림이 연결되므로 실제 그림 연결 강의는40강이다.

## 정본과 보존 범위

- [63강 정본](../content/course-pack.json): 5개 단원, 63강, 490개 개념, 95개 예제, 189개 자기점검, 223개 입력·결과표, 70개 SQL 블록, 기존 개념도63개를 유지한다. 강의·예제·자기점검 ID를 바꾸지 않았다.
- [그림과 설명 정본](../content/course-visuals.json): 그림27개, 강의 연결45건, 강의별 검토63건. 그림 데이터와 기존 SQL 예제 데이터는 구별한다.
- 원자료 `content.json`과 `curriculum.json`에는 별도 `learningObjectives` 배열이 없다. 실제 학습 내용인 `easy`, `why`, `concepts`, `memory`, `traps`, 예제·자기점검을 대조했다. 존재하지 않는 목표 필드를 보존했다고 주장하지 않는다.
- 기존 CHECK·CASE·GROUPING_ID 정정, 논리 처리 도해의 ORDER BY, 생략된 암기 문장 복원 등 이전 정정을 유지했다. 기존41개 노트·661개 채점문항의 내장 팩은 이번 작업 전 해시와 같다.
- 아래 세 콘텐츠 정정 외 원래63강의 SQL·입력표·결과·정답을 바꾸지 않았다. 디비전 정정은 원래 이름·과목 셀과 결과를 보존하면서 식별자 열을 추가한 예외이며, 무변경으로 표시하지 않는다.
- 기존 학습 저장 항목을 삭제하거나 초기화하는 변경은 없다. 디비전 강의의 `version`만1에서2로 올려 기존 `readVersion=1` 기록을 유지하면서 보강 내용 확인 전임을 표시한다. 실제 저장 샘플의 갱신 전후 증거와 최종 실행 결과는 [QA](QA.md)에 따로 기록한다.

강의별 판정의 최초 독립 AI 검토는 [검토 기록](../evidence/visuals-lesson-review.json), 실제 반영값은 두 정본 JSON을 따른다. 원자료 제작자의 검증 주장, 이번 AI 내용 검토, SQL 엔진 실행, Android 실행, 사람 검수는 서로 다른 증거다.

## 표시 흐름과 정답 공개 시점

쉬운 뜻을 먼저 읽고 해당 강의에 연결된 경우에만 **그림으로 먼저 이해하기**에서 그림·읽는 순서·독립 입력표·결과 이유를 확인한다. 이어 기존 개념·SQL·단계별 예제와 자기점검으로 진행한다. 같은 번호나 이름이 등장하더라도 서로 다른 예제의 값이 같다고 가정하지 않는다.

기존 예제 화면 첫 안내는 다른 데이터로 연습한다는 사실만 알린다. `exampleReadingGuide`에는 결과가 포함될 수 있어 **그 강의의 모든 예제 결과를 펼쳐 본 뒤에만 ‘그림과 예제 비교 해설’로 표시**한다. 입력표를 보고 결과를 예상하는 기존 흐름에 답을 먼저 노출하지 않는다. 기존 단계 이동·결과 펼치기·자기점검 답안 공개는 그대로 사용한다.

그림은 정적인 설명 자료다. 그림 자체가 SQL을 실행하거나 행 처리 단계를 자동 재생하는 것은 아니다. 논리적 읽기 순서는 실제 DBMS의 물리 실행계획과 구별하며, 관계대수 SELECT(σ)는 SQL의 SELECT 절과 동일시하지 않는다.

디비전은 ‘필수 DB·JAVA를 모두 수강한 학생’이라는 질문을 바꾸지 않았다. 서로 다른 두 동명이인의 DB와 JAVA를 합쳐 한 학생이 이수한 것처럼 계산하던 연결 기준을 수정했다. 결과는 기존처럼 이름만 보여 주며, 동명이인을 결과에서도 각각 구분해야 하는 실제 설계라면 학번도 함께 출력해야 한다는 설명을 추가했다. [정정 기록](../content/course-visual-corrections.json)의 전후 값과 엔진 fixture를 함께 관리한다.

정정 기록을 그대로 정답으로 믿는 검사는 하지 않는다. [원본 보존 회귀 검사](../scripts/test_course_content.py)는 독립적으로 고정한 두 문장과 디비전 전후 값만 허용하고, 나머지 원본 정규화 객체 전체를 현재 팩과 비교한다. SQL 엔진 검사는 표시 SQL·표와 fixture의 동일성도 확인한다. Oracle 전용 문법을 SQLite 대체식 성공만으로 실행 검증 완료라고 표시하지 않는다.

## 그림20 정정과 원본 보존

CUBE 그림의 `(과목)` 소계에서 `()` 전체 합계로 이어지는 화살표 문구를 **‘지역 제거’에서 ‘과목 제거’로** 수정했다. 지역은 그 단계에서 이미 집계 기준에서 빠졌으며, 마지막에 제거하는 기준은 과목이다. 이름·수치·표·계산 결과는 바꾸지 않았다. 통합 SVG에서 파생 PNG를 다시 렌더링해 표시하며, PNG의 글자를 앱 표시값처럼 바꾸지 않는다.

[원래 SVG](../content/course-visuals/originals/visual-20.svg)와 [원래 PNG](../content/course-visuals/originals/visual-20.png)는 삭제하지 않고 보존한다. 통합본은 `content/course-visuals/visual-20.svg` 및 `.png`이고 [렌더 증거](../evidence/visuals-corrections/render-evidence.json)는 이미지 재생성 환경만 기록한다. 이 그림 정정은 위 세 강의 콘텐츠 정정과 별개다.

## 검증 범위와 최신 결과

이 문서는 반영한 내용과 보존 계약을 기록한다. 실제 최신 검사 결과·실패·미검증 사항은 [QA](QA.md)와 해당 실행 로그를 따른다. 본 문서 작성 시점에 완료되지 않은 최종 기기 검사 수치나 성공률을 미리 적지 않는다.

재검사 명령은 `python scripts/validate_course.py --engine`, `python scripts/validate_visuals.py`, `python -m unittest discover -s scripts -p 'test_*.py' -v`이다. 이는 구조·자료 일치·실행 가능한 SQL 범위를 검사하며 사람 전문가 검수, 공식 출제범위 전체 충족, 실제 학습효과 또는 합격 보장을 뜻하지 않는다.
