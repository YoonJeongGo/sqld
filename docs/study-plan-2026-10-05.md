# SQL 노트 0.5.0 — 40일 학습 계획

작성일: 2026-10-05. 사용자 제공 강의 104개, 교재 PDF 5권 324쪽, 기존 앱의 학습 내용을 하나의 날짜별 계획으로 연결했다. Canva 수정 저장은 사용자가 보류하여 앱과 로컬 PDF를 최종 사용 자료로 삼는다. 원본 교재·강의 영상은 앱에 복제하지 않는다.

## 학습량과 기간

- 2026-10-05~11-13의 40일 중 주말과 10/8·9를 제외한 **28공부일, 12휴식일**.
- 5시간은 순공부 300분 × 28일 = **140시간**. 6시간은 같은 진도 + 약점 보완 60분 × 28일 = **168시간**. 식사·휴식은 별도다.
- 이론 63강 1,932분 + 개념완성 25강 787분 + 모의 해설 15강 745분 + 정규식 특강 57분 = **104강 3,521분(58시간 41분)**.
- 기본 계획에서 영상 외 풀이·복습·정리에 81시간 19분을 남겼다. 영상은 1배속 순재생 시간이며 정지·필기·재생은 추가 시간을 쓴다.
- 10/5~10/28: 이론 63강·정규식 특강, PDF 전체 범위 첫 학습. 10/29~11/5: 개념완성 25강 및 미풀이 보완. 11/6·9·10·11·12: 모의 5회. 11/13: 밀린 분량과 오답 정리.
- 11/14는 사용자 목표일을 반영했다. 공식 시험일 확인 또는 합격 보장이라는 뜻이 아니다.

전체 날짜별 강의·쪽수·5시간/6시간 배분은 `output/pdf/SQLD_40일_전체학습계획_5시간_6시간.pdf`, `output/study-plan/전체계획표.html`, `전체계획표.csv`, `전체계획표.md`에 있다.

## 학습 방법과 범위 구분

강의는 개념 이해, PDF는 직접 풀이, 앱은 회상·기존 예제·연습·오답 복습으로 쓴다. 앱의 부족한 세부 조건은 해당 날짜의 PDF 핵심 항목에 표시했다. PDF 내용을 앱이 전부 포함한다거나, 앱 문제 정답을 외우면 원문을 모두 풀 수 있다고 판정하지 않는다.

교재 쪽수는 PDF 파일 첫 쪽을 1로 센다. 소제목이 같은 쪽에 이어지는 경계는 겹칠 수 있다. 10/29 이후 쪽수는 약점 참고 범위이며 해당 문제풀이 회차의 실제 출제 범위나 전 범위 재독 지시가 아니다.

3-1 회차별 원문과 3-2 모의고사 원문은 제공된 이론 PDF 5권에서 확인되지 않았다. 강의 첨부 원문을 보유한 경우 먼저 풀고 해설을 본다. 없으면 교재 오답 또는 앱 미열람 모의를 사용하고 해당 자료 자체 해설로 별도 채점한다. 강의의 다른 예제와 점수를 섞지 않는다. 앞서 언급한 별도 파이널 10회·30강은 이번 104강 목록에 없어 기본 계획에 넣지 않았다.

해설이 긴 11/6·9에는 오답 검토가 남을 수 있다. 남은 문항을 추가 60분 또는 11/13 보완 시간으로 넘긴다. 주말에 밀린 분량을 자동 배정하지 않는다. 처음 보는 모의 3회 75~80점, 반복 오답 감소, 이유 설명을 개인 점검 목표로 제시했으며 공식 합격 기준이나 효능 검증 결과가 아니다.

## 앱 변경

- 홈의 **학습 계획** → 날짜 선택 → **5시간 기본 / 6시간 확장**.
- 날짜별 시간 배분, 강의 번호·제목·분량, PDF 파일·쪽수·확인할 규칙 표시.
- 기존 63강·개념 노트·연결 연습으로 이동. 일반 연습에서 모의고사 문항과 사용자 제외 문항을 배제한다.
- 실전 모의 중 계획을 열 때도 기존 연습 전환 확인을 적용한다.
- 휴식일에는 학습을 배정하지 않으며 다음 공부일로 이동할 수 있다.
- 영상 시청·PDF 풀이 완료를 앱 노트 읽음으로 기록하지 않는다. 새로운 DB 테이블이나 StudyState 필드는 없다. 날짜·시간 선택은 화면 상태다.
- 실제 휴대폰에서 일일 제목의 '스키마'가 중간에 끊긴 것을 발견하여 해당 제목 크기·구분자 공백·줄바꿈 규칙을 수정했다.

구현 파일: `StudyPlan.kt`, `PlanScreens.kt`, `MainActivity.kt`, `LearningScreens.kt`; `app/build.gradle.kts`의 버전은 0.5.0 / 10이다. 기존 콘텐츠·학습 모델·저장소·채점 엔진·백업 형식은 변경하지 않았다.

## 재생성과 빌드

`scripts/create_study_plan.py`는 `content/course-pack.json`의 강의 목록과 `content/study-plan-pdf-map.json`의 대조된 PDF 쪽수를 읽어 날짜별 계획을 만든다. 앱과 산출물의 `study-plan.json`은 동일한 바이트다. 이 생성기는 원래 강의·문제 콘텐츠를 덮어쓰지 않는다.

```powershell
python scripts/create_study_plan.py
# reportlab 설치 환경에서 실행. 이 PC는 Codex 제공 Python 런타임을 사용했다.
python scripts/render_study_plan.py
python scripts/validate_content.py --strict
./scripts/build.ps1 -Tasks testDebugUnitTest,assembleDebug,assembleDebugAndroidTest,assembleRelease -Offline
python scripts/package_artifacts.py --build-type release
```

PDF 렌더러는 Windows의 맑은 고딕 폰트를 사용한다. 계획은 `content/study-plan.json`을 기준으로 앱·PDF·HTML에 표시한다. 생성 후 직접 JSON만 바꾸면 다음 생성에 덮어쓰이므로 날짜·학습량 변경은 생성 코드와 PDF 매핑 자료에서 한다.

## 실제 검사와 보존

- 변경 전 `testDebugUnitTest` 빌드 성공은 캐시 재사용이 포함된 기준 확인이었다. 변경 후 실제 JVM 검사 **76개 통과**. 새 계획 테스트 4개가 포함되며 이전 버전 검사와 합산하지 않았다.
- 실제 Compose `StudyPlanUiTest` **3개 통과**: 날짜·시간 복귀, 휴식일 기록 무변경, 강의·문제 연결, 실전 전환 확인. 별도 in-memory DB를 사용한다.
- 독립 데이터 검사: 40일/28공부일/12휴식일, 104개 고유 강의, 63강 연결, 324쪽 첫 학습 배정, 일별 300+60분, 모의 문항 배제, JSON 복제본 일치, 문제 0개. `evidence/study-plan-20261005/independent-plan-check.json`.
- `validate_content.py --strict` 성공. 기존 콘텐츠 팩 3개의 SHA-256은 변경 전과 같으며 APK 안의 파일도 원본과 일치한다. 구조 검사는 문항 정답 전체 검증·DBMS 실행을 의미하지 않는다.
- PDF 17쪽 전체를 이미지로 렌더링하여 한글·잘림·줄바꿈을 확인했고 긴 SQL 제목을 조정했다. `tmp/study-plan/render/`에 최종 렌더가 있다.
- 전용 Android 에뮬레이터에서 휴대폰, 태블릿 가로, 200% 글씨 화면을 확인했다. 실제 Galaxy Tab 검사와 구분한다.
- 갱신 전 실제 기존 기록을 앱의 전체 백업으로 저장하고 가져오기 미리보기 검증 뒤 취소했다. 삭제·초기화·실제 복원은 하지 않았다. 제출 55개·메모/필기·별표·복습·노출·강의 진도 등 보호 항목은 보존됐다. 디버그 QA 중 이전 미완료 세션을 표시하면서 시간·스크롤·revision은 정상적으로 증가했고 이를 전체 동일이라고 보고하지 않았다.

원본 자료와 실제 기록 비교의 상세 근거는 `evidence/study-plan-20261005/`에 있다. `private-*.json`은 로컬 개인 백업으로 외부 산출물과 소스 ZIP에서 제외한다. 최종 릴리스 검사와 기록 비교는 [기기 QA 보고서](study-plan-qa-2026-10-05.md)를 확인한다.

최종 제목 수정 후 `testDebugUnitTest,assembleDebug,assembleDebugAndroidTest,assembleRelease` 빌드는 성공했고 JVM 76개가 통과했다. 최종 debug APK의 UI 3개도 30.583초에 다시 통과했다. `tmp/study-plan-final-build.log`, `evidence/study-plan-20261005/final-study-plan-instrumentation.log`가 근거다. 초기 일반 권한 빌드는 SDK `android.jar` 접근 제한으로 실패했으며 허용된 권한으로 재실행해 성공했다.

최종 릴리스는 `install -r`로 설치했고 360dp 휴대폰·1280×800dp 태블릿·320dp/200% 글씨에서 직접 확인했다. 200%에서도 제목의 '스키마'가 유지되었고 6시간의 추가 20+25+15분 및 휴식일 이동이 정상 동작했다. 최종 debug→release의 전체 백업 payload는 SHA-256과 내용이 완전히 동일했다. 초기 0.4.1→최종 릴리스의 차이는 QA 중 사용한 기존 미완료 세션 시간·스크롤·revision만이며 보호 필드 13개는 동일하다. 화면 크기·밀도·글씨·야간 설정을 원래 값으로 복구했다.

## 되돌리기

작업 전 234개 파일의 복원용 ZIP은 `backups/study-plan-before-20261005-193457.zip`이다. `app/build.gradle.kts`는 이전 배포 소스 ZIP의 원본과 현재 파일을 비교하여 버전 두 줄만 달라졌음을 확인했고, 원본을 `backups/study-plan-app-build-0.4.1.gradle.kts`에 별도 보존했다.

전체 폴더를 덮어쓰거나 앱 데이터를 지우지 않는다. 계획 기능만 되돌릴 때는 작업 전 MainActivity/LearningScreens와 버전 설정을 별도 작업 복사본에서 복원하고, 추가한 PlanScreens/StudyPlan 및 테스트·계획 자산을 제거하여 새 버전 번호로 빌드한다. 기존 APK는 `dist/SQL-note-0.4.1-release.apk`에 보존했지만 Android의 버전 다운그레이드 제한을 피하려고 앱을 제거해서는 안 된다. 같은 서명으로 업데이트하고 기록 백업·미리보기·검증 절차를 유지한다.

## 미검증 사항

실제 Galaxy 기기, 모든 기존 UI 회귀 테스트의 재실행, 이번 계획의 실제 학습 효과, 사용자 현재 실력, 모든 교재 문항 정답의 독립 검증, Oracle/SQL Server 실제 실행, 현행 공식 출제범위·일정의 확인은 이번 작업의 완료 항목이 아니다. Canva의 수정 초안은 사용자 요청으로 저장을 보류했다.
